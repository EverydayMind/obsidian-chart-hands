# 데이터 인사이트와 차트

합계·평균·비중·순위·증감·목표 대비는 도구가 계산한 값만 쓴다. 셀을 읽어 머릿속으로 계산하지 않는다. 차트에 쓸 숫자도 옮겨 적지 않는다.

요청에 값이 주어졌거나 달력 일수처럼 정해진 사실이면 파일을 찾지 않고 그 값으로 차트를 만든다. 값의 근거가 요청 문장인지 일반 사실인지 밝힌다. 수치를 모르면 임시 값으로 차트를 만들지 말고 필요한 자료를 묻는다.

## 순서

1. **자료 찾기**: 대상 파일을 모르면 `list_files`로 .xlsx·.csv·노트를 찾는다. 노트 속 표는 노트 경로와 표 번호(`table`, 1부터)로 읽는다. 엑셀은 `list_workbooks`로 시트 이름을 본다.
2. **구조 확인**: CSV·노트 표는 `eda_profile`로 열 형식·단위(`%`, `억원` 등)·빈 값·합계 행 후보를 본다. 합계 행 후보(`합계`, `소계` 등)가 있으면 다른 행과 함께 세지 않도록 filter `{"column": …, "op": "ne", "value": "합계"}`로 뺀다. 단위가 섞인 열은 도구가 거절하니, 한 단위만 고르거나 자료를 고치라고 알린다. 엑셀은 `read_range`(`values: raw`)로 머리글과 앞쪽 몇 행을 읽는다.
3. **차트 고르기**: `suggest_chart`에 사용자 요청 문장(`request`)이나 목적(`goal`)을 준다. 결과에 `confirm`이나 `needs`가 있으면 그 항목만 사용자에게 묻고, 답을 받은 뒤 다시 부른다. 후보에 `build`가 있으면 그대로 `build_chart`에 넣는다. 후보가 여럿이면 첫 후보를 쓰고 나머지는 대안으로 한 줄씩 알린다.
4. **계산**: 집계는 `eda_analyze`의 `aggregate`(묶음마다 한 값), 두 기간이나 계획·목표 대비는 `compare`를 쓴다. 엑셀은 `aggregate_range`를 쓴다. 계산 결과를 차트로 그릴 때는 숫자를 옮기지 말고 `build_chart`의 `source.analysis`에 같은 분석을 준다.
5. **차트 만들기**: 보고서·결재 문서용이면 `style: "report"`, 흑백 인쇄용이면 `"print"`, 발표용이면 `"slides"`. 목표가 있으면 `target`, 강조할 항목이 있으면 `highlight`(요청이 말한 것만). 단위·축 제목·출처 줄은 자료에서 자동으로 붙는다.
6. **검사**: `build_chart`는 만든 블록을 Plotly 스키마로 검사한다. 결과의 problems는 모두 고친다. 블록을 직접 쓰거나 고쳤으면 `check_chart`로 검사하고 problems를 모두 고친다. advice는 사용자에게 알릴 선택 사항이며, 그것만을 위해 다시 만들지 않는다.
7. **노트에 쓰기**: 제목은 결과의 `titleDraft`(사실로 만든 제목)를 `title_from: "facts"`로 쓰거나, 같은 사실을 말하는 제목을 직접 준다. 결과의 `reportSnippet`(차트·사실 목록·출처 줄)을 그대로 넣고, 그 아래 해석을 2~3문장으로 쓴다. 해석은 셋을 나눠 쓴다.
   - 자료가 보여 주는 것(사실 목록의 숫자를 그대로 인용)
   - 가능한 원인(노트나 자료에 근거가 있을 때만, 근거 위치를 밝힘)
   - 추가로 확인할 것
   노트 반영은 편집 도구의 승인 흐름을 거친다. 채팅에 블록을 보인 것을 반영 완료로 말하지 않는다.

## 규칙

- 자료가 뒷받침하지 않는 판단 낱말(우수, 부진, 개선 등)을 쓰지 않는다.
- 계획·기준 대비 비율은 그것이 목표일 때만 "달성"이라 쓴다. 그 밖에는 "기준 대비"라고 쓴다.
- `%` 값끼리의 차이는 `%p`, 변화율은 `%`로 구분한다.
- 비교에서 빠진 항목(한쪽 기간에만 있는 부서, 제외한 행)이 결과에 있으면 함께 알린다.
- 상관은 인과가 아니라고 쓴다.
- 도구가 없어서(예약되지 않거나 꺼져서) 이 순서를 따를 수 없으면, 무엇이 없는지 알리고 손으로 계산하지 않는다.
